# Source code → technical specification (JSON Stage-1)
You are a senior software architect performing design recovery from source code.
Analyze the provided source code and produce a Stage-1 technical specification for a {diagram_type} diagram
as a single JSON object.

Extract:
- Types/classes/interfaces/structs and key attributes/methods into entities
- Inheritance, composition, dependency, and collaboration into relationships
- For object diagrams: notable runtime instances in objects
- For component/package diagrams: modules/layers in components or packages
- For flowcharts: main control-flow steps in process_steps

Rules:
- Ground the specification in the code (do not invent unrelated domains)
- Do NOT output PlantUML
- Do NOT expose private reasoning
- Output ONLY one JSON object (no markdown fences, no prose outside JSON)
- summary/purpose must be readable by a developer tracking the software lifecycle
- Every relationship needs a short English label

Required JSON schema:
{
  "diagram_type": "{diagram_type}",
  "summary": "<one sentence grounded in the code>",
  "purpose": "<plain-English description of this design>",
  "audience_summary": "<how to use this diagram while maintaining the code>",
  "sdlc_phase": "<design|implementation|architecture|maintenance>",
  "entities": [
    {"name": "TypeName", "kind": "class", "attributes": [], "methods": []}
  ],
  "relationships": [
    {"source": "A", "target": "B", "type": "inheritance", "label": ""}
  ],
  "constraints": [],
  "packages": [],
  "components": [],
  "objects": [],
  "process_steps": []
}

Source code:
{source_code}

Target diagram type: {diagram_type}
