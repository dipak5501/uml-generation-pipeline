## What training data contains

### Open Hugging Face UMLCode sources

Assembled by `scripts/build_training_corpus.py` and `scripts/download_all_corpora.py`:

- nguyenvanviet UMLCode class/object/component/package/state/deployment scored sets
- Activity / flowchart / sequence / use-case corpora
- Web PlantUML (e.g. the-stack-v2 filtered)
- Optional gated class-scored set (`HF_TOKEN` + license)

Inventory: `data/data_lake_inventory.json`, `data/training/manifest.json`

### 50k web/HF corpus

```bash
make train-50k
```

Produces `data/training/uml_training_*.parquet` (~50k unique rows) and finetune JSONL via `prepare_finetune_data.py`.

### 50k source-code corpus

```bash
python scripts/build_source_code_corpus.py --target 50000
```

Rows include `input_mode=source_code` with:

- Web full-stack snippets (the-stack-v2 PlantUML filtered)
- Multi-language synthetic code top-up
- HF instruction pairs (`input_mode=requirement`)

Manifest: `data/training/source_code_manifest.json`  
Parquet: `data/training/uml_source_code_50k.parquet`

### 100k combined merge

```bash
make train-100k
```

Merges 50k HF/web + 50k source-code → `data/training/uml_training_combined_100k.parquet` (~102k rows).  
Finetune splits: `data/finetune/{train,valid,test}.jsonl` (~131k train lines with `--prefer-accepted` upsampling).

## Finetune JSONL format

Each line (MLX-LM chat format):

```json
{
  "messages": [
    {
      "role": "system",
      "content": "You are a UML expert… output ONLY valid PlantUML… Black-and-white UML only…"
    },
    {
      "role": "user",
      "content": "Target diagram type: class\n\nTechnical specification:\n…"
    },
    {
      "role": "assistant",
      "content": "@startuml\nclass Order { … }\n@enduml"
    }
  ]
}
```

### `input_mode` field (in source parquet)

| Mode | User prompt includes |
|------|---------------------|
| `requirement` | Technical specification only |
| `source_code` | Source code context + language label + specification |

Generated by `scripts/prepare_finetune_data.py` from parquet columns `input_mode`, `source_language`, `source_requirement`, `technical_spec`, `uml_code`, `diagram_type`.

## Train commands

```bash
pip install -r requirements-finetune.txt

# Step-by-step (8k legacy)
make training-corpus
make finetune-prepare
make finetune

# Full 50k path (complete)
make train-50k

# 100k path (may take days; resilient to interruptions)
make train-100k

# 30k per-language source-code (Java/Python/C 10k each) — production default
make train-source30k
```

Resilient runner (Open MPI-safe, auto-resume): `scripts/run_finetune_resilient.sh`

Hyperparameters (50k/100k): batch 2, max_seq_length 1536, lr 1e-5, LoRA 8 layers. Logs: `data/training/finetune_50k.log`, `finetune_100k.log`.

## Train (NVIDIA CUDA)

Apple MLX adapters **will not load**. Retrain with PEFT:

```bash
pip install -r requirements-finetune-cuda.txt
make finetune-cuda
# or: make train-real   # auto-detects CUDA
```

Then in `.env`:

```bash
USE_FINETUNED_CODE=true
FINETUNED_BASE_MODEL=Qwen/Qwen2.5-0.5B-Instruct
FINETUNED_ADAPTER_PATH=models/uml-plantuml-lora
```

Full GPU-machine checklist: [docs/CURSOR_GPU_HANDOFF.md](../docs/CURSOR_GPU_HANDOFF.md).

## Enable in the running app

`.env`:

```bash
USE_FINETUNED_CODE=true
MOCK_PROVIDERS=false          # or true — LoRA still used for PlantUML when enabled
USE_OLLAMA=true               # spec + VLMs stay on Ollama
FINETUNED_BASE_MODEL=mlx-community/Qwen2.5-0.5B-Instruct-4bit
FINETUNED_ADAPTER_PATH=models/uml-plantuml-lora-sourcecode-30k   # production Mac Studio default
FINETUNED_MAX_TOKENS=1536     # 512 truncates complex class/package diagrams
```

Restart:

```bash
bash scripts/restart_api.sh
# or
./scripts/run_local.sh
```

Only the **PlantUML code** stage uses the LoRA adapter. When enabled, generation prefers LoRA for class/object/component/package (API types), then falls back to the grounded spec-builder if validation or fidelity checks fail.

Package diagrams may still route to base Ollama or typed templates when LoRA output fails diagram-type validators.
